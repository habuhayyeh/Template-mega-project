# DECISIONS

Permanent. A decision changes only by a new decision that names the old one.

| ID | Decision |
|---|---|
| D-001 | Six semantic kinds — `DEMOGRAPHIC`, `OBSERVATION`, `COURSE`, `MANAGEMENT`, `DIAGNOSTIC_FORMULATION`, `ETIOLOGY`. No reasoning kind; reasoning is compositional and is carried by formulation and etiology objects. |
| D-002 | The A/P derives from the Handoff only. `05` never reads the sources. |
| D-003 | One frozen substrate feeds both branches. Neither branch consumes the other's intermediate output. |
| D-004 | Explicit current-clinician reasoning outranks downstream inference. Where the clinician stated a formulation, etiology or adjudication, the pipeline organizes it rather than reconstructing a substitute. |
| D-005 | `02` and `05` are prose modules. Their code-spec versions are superseded and live only in history. |
| D-006 | Production `06` is unresolved. The section contract and the reviewed ledger are accepted; Doximity runs of `06` are not reliable enough to run unattended (3 runs: 12, 6, 9 unacceptable differences; schema broken on the third). |
| D-007 | `04` dereferences O# and appends provenance verbatim. Provenance is never added to the `03` ledger. |
| D-008 | `EVIDENCE_MODE` is required on `OBSERVATION` and `COURSE` only; it is routing metadata and never appears in prose. |
| D-009 | One writer per path. The reviewer writes `reviews/` only. |
| D-010 | No real patient data in the repository. Synthetic or de-identified only. |
| D-011 | The three contract edits imported in `import/v2` are ratified as baseline: `03` exclusive evidence eligibility and reasoning protection, `04` exemption of reasoning from duplicate deletion, `05` reasoning rendering rules. They are not re-proposed. |
| D-012 | Agent conversation runs through `channel/`, two single-writer files. The channel is conversation, not state: agreement is recorded in `DECISIONS.md`, currency in `STATUS.md`. No push-to-chat trigger exists; the loop uses a one-line prompt. |
| D-013 | Escalation rule. Either agent stops and asks the user when the two agents disagree without repository evidence, when a contract is genuinely ambiguous, when the choice is clinical, stylistic or product, or when the alternative is guessing. Mechanical choices are not escalated. The answer becomes a `D-###`. |
| D-014 | O54 residual mild expressive aphasia stays out of the A/P. It is sequela context for the old infarct, which O7 and O18 already establish; admitting the [D] copy after excluding the [A] copy as context would be indefensible. The fact remains in the body note. The A/P does not need every retained entry to render. |
| D-015 | Chronic-block rule. A chronic neurologic problem gets its own shorter A/P block when the encounter contains a management decision directed at that problem. Diagnosis alone, or a listed home medication alone, does not create a block. The decision must be source-grounded as directed at that chronic problem in this encounter; the target is never inferred from drug class or general knowledge. Active problems are ordered first. The block carries problem-defining facts, the reasoning that explains it, and the management directed at it. Non-neurologic problems do not become blocks unless they materially affect neurologic assessment or management. |
| D-016 | Scope of the pre-05 fixes is narrowed (signer, 2026-11-15). P006 stays the explicit render/compose grouping fix for the instability demonstrated in clean set 3. COURSE typing, evidence include-flags, management canonicalisation and standing-item injection are **not** adopted now; a broader P007 may be proposed only if residual instability after P006 demonstrates the need. No broader pre-05 normalisation is added on the strength of an external audit whose package provenance was wrong. |
| D-017 | Impersonal A/P voice (signer, 2026-11-15). Rendered A/P prose carries no first-person `I` or `we`; conversational source wording may, and is converted by one bounded surface transformation that removes the first-person framing and preserves the clinical proposition. The MRI adjudication renders as `MRI to show.` — the fuller `MRI to show whether there is a new lesion` is not used because it repeats the comparator already on the problem line. The conversion is bounded to voice; it is not a general paraphrase licence. |
| D-018 | Supersedes D-009 for bounded implementation work in the architecture-reboot implementation phase (signer, 2026-11-15). Coordination/review paths remain single-writer, but ChatGPT may directly patch localized implementation defects when the accepted contract/tests make the correction unambiguous and the patch does not alter architecture, module ownership, frozen interfaces, predicate meaning, experiment hypotheses, oracle semantics, or clinical/style/product policy. ChatGPT must add or adjust validation/tests where applicable, commit the patch, and hand the exact commit to DeepSeek for independent review. DeepSeek remains the primary engineer/co-engineer for broader implementation and must independently review ChatGPT direct patches; neither agent may treat its own implementation as self-validating. Design/contract changes still require the proposal/review/user-decision path unless the user explicitly directs otherwise. |
| D-019 | Efficiency protocol for architecture-reboot (signer, 2026-11-15). Reviews are scope-limited to the declared diff and dependency cone unless evidence requires widening. Findings are classified as ARCHITECTURE, CONTRACT, IMPLEMENTATION, or NONBLOCKING; implementation defects are fixed directly under D-018, while architecture/contract issues use governed change. A layer stops being reviewed once its governing contract is satisfied, required validators pass, evidence is reproducible, and no result-invalidating or materially misleading defect remains; reopening requires new evidence such as a failing test, counterexample, implementation result, or contradiction. Handoffs use COMMIT/TYPE/CHANGED/INVARIANTS/VALIDATION/BLOCKERS/NEXT. DeepSeek and ChatGPT work asymmetrically and the non-author reviews the actual diff. Recurring mechanical checks are consolidated behind a preflight entry point; semantic/human prerequisites block semantic acceptance, not safe mechanical preparation. |
| D-020 | No status-only project updates (signer, 2026-11-15). Every substantive sync, review, closure, handoff, or user-facing project update from either agent must include a concrete NEXT action. NEXT names the next task or decision and, where relevant, the responsible actor. If blocked, the update names the blocker and the exact action/decision required to unblock it. If no new work landed, the update still names the next authorized action. Closing a layer must immediately identify the next dependency/workstream. A status table or “state unchanged/ready” message without NEXT is incomplete. If signer input is required, ask the narrow decision question and give a recommendation; otherwise proceed with the next authorized mechanical/implementation task instead of merely reporting it. |
| D-021 | Gate 0 semantic calibration policy, Option F (signer, 2026-11-15). The signer/clinician records a blinded reference verdict first: clean packet SILENT, seeded packet FIRED. Two blinded LLM evaluators in separate packet-only sessions, from different model families where available, must exactly match the reference and satisfy within-layer specificity. A determinate mismatch is FAIL; missing, duplicate or genuinely UNDECIDABLE evidence is INCOMPLETE; there is no majority pass. Signer references are reused while packet, predicate/contract version, oracle/context hashes and policy version are unchanged. Evaluator evidence is reused only for the same packet, policy, judge and model family/version. Project-context agents are not fresh evaluators. This supersedes the three-independent-human Gate 0 calibration rule. Gate 0 remains UNRUN. |
| D-022 | Option F explicit ratification and sync semantics (signer, 2026-11-15). The signer explicitly confirms approval of Option F for the Gate 0 harness, ratifying D-021 and its implementation. Separately, `.` / `sync` remains synchronization shorthand only and does not itself constitute approval of a pending proposal; approval must be explicit elsewhere in the authorized interaction. |
| D-023 | Major inactive neurologic problem retention (signer, 2026-11-15). A major established neurologic diagnosis that is itself a primary neurologic problem (CASE-01 example: prior left MCA infarct) may retain its own A/P problem even when inactive and even when no new management decision is directed at it in the current encounter. Inactivity changes rendering depth: the problem should be shorter/condensed, not automatically removed. This partially supersedes D-015: its current-management prerequisite does not apply to such major primary neurologic diagnoses; D-015 continues to govern other chronic neurologic problems unless separately revised. Current-adoption status and A/P problem retention are therefore not equivalent decisions. |
